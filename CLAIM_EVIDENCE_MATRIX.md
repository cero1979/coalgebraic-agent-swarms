# Claim-Evidence-Limitation Matrix

This matrix is the audit boundary for the *Array* revision. Numerical claims
must be regenerated from `experiments/results/summary.json`; prose should not
broaden the corresponding limitation column.

| Claim | Direct evidence | Recorded result | Boundary or limitation |
|---|---|---|---|
| Raw framework behavior can be separated from resource-certified behavior. | `main.tex`; `paper/figures/certification_architecture.tex`; checker transition interface | A canonical event is admitted only after the configured certificate checks succeed. | This is the paper's architecture, not a claim that the framework itself supplies certificates. |
| The certificate layer tracks permissions, budgets, routing, memory, provenance, claims, and audit evidence. | `prototype/checker.py`; `prototype/rules.json`; `prototype/test_checker.py` | The implemented event schemas return structured obligation codes and commit only validated transitions. | Fixed side-conditioned fragment; no complete SELL proof search, focusing completeness, or mechanised metatheory. |
| Standard coalgebraic behavior is preserved when restricting to certified runs under the stated hypotheses. | Formal definitions and cited standard coalgebraic results in `main.tex` | Conditional preservation and prefix-safety statements are proved at manuscript level. | Requires locally sound rules and a source-well-formed initial ledger; deterministic Moore/Mealy scope; standard coalgebra is background, not claimed as a new abstract coalgebraic construction. |
| Disjoint components admit the stated interleaving result. | Composition statement and proof in `main.tex` | The result applies under explicit disjointness and independence hypotheses. | No theorem for arbitrary shared memory, shared budgets, cyclic dependencies, or general framework composition. |
| The fixed conformance suite behaves as specified. | `prototype/traces/`; `experiments/results/conformance_results.{json,csv}`; generated conformance table | E1: 19/19 expectation matches, comprising 5 accepted and 14 rejected traces over 55 events. | Handcrafted finite synthetic fixtures; the suite is not exhaustive over all JSON inputs or policies. |
| Three real LangGraph workflows can be captured, normalized, and accepted. | `integrations/langgraph/workflows.py`; `run_workflows.py`; `adapter.py`; `experiments/results/framework_runs.json` | E2: 3/3 LangGraph 1.2.11 `StateGraph` workflows accepted; 63 native records mapped to 23 canonical events. | One framework, three deterministic local workflows, no LLM or external service; not production-scale validation. |
| The adapter is grounded in framework output rather than a hand-written substitute trace. | Captured v2 `tasks`, `updates`, and `values` in `framework_runs.json`; adapter tests | Native records are retained alongside the derived canonical events. | Application nodes explicitly instrument domain meanings. LangGraph does not infer permissions, costs, factual truth, or provenance of uninstrumented effects. |
| Each seeded certification fault is detected as intended. | `experiments/mutations.py`; `mutation_results.{json,csv}`; mutation tests | E3: 42/42 mutants strictly detected, covering 14 categories across three source traces, with zero unexpected accepts. | Mutations are known controlled faults derived from the same three accepted traces; no claim about unseen attacks, false positives, or adversarial robustness. |
| Checker runtime is measured over increasing accepted trace lengths. | `experiments/scaling.py`; `runtime_results.{json,csv}`; `environment.json` | E4: 10, 100, 1,000, 5,000, and 10,000 events; one warmup and seven measured repetitions at each length. | Alternating communication-only events; excludes input-copy preparation, framework execution, model inference, network latency, and other event mixes. Timings are machine-dependent. |
| The reported expected-time argument refers to the refactored implementation. | Indexed rule construction and validate-then-commit loop in `prototype/checker.py`; manuscript complexity analysis | Specification indexing and a single trace pass avoid the former per-step growing-state copy pattern. | Expected `O(s+N)` is stated only for a hash-table word-RAM model with identifiers, costs, and budgets occupying `O(1)` words; arbitrary-precision arithmetic, serialization, and caller-side preparation are outside that bound. The empirical benchmark does not prove asymptotic complexity. |
| Results and tables can be regenerated and checked for snapshot integrity. | `experiments/run_all.py`; both `MANIFEST.json` files; `paper/generated/`; `make experiments`; `make verify` | JSON/CSV outputs and four LaTeX tables are regenerated from source inputs and checked with SHA-256 inventories. | Native task identifiers and timings can change on rerun. Manifest verification checks consistency of only the current local snapshot, not authorship or public immutability. |
| Evaluation data are original to this study. | Committed E1 fixtures; deterministic workflow code; mutation and scaling generators | All E1--E4 inputs and outputs are synthetic or programmatically generated. | No human/third-party dataset is used; bibliographic-looking fixture strings are not observations from a reference corpus. |
| Certified provenance and claims satisfy the encoded structural obligations. | Checker provenance, certificate-source, certifier, and answer-support checks; E1/E3 controls | Missing or malformed structural evidence is rejected by the relevant configured rule. | A nonempty provenance record is not cryptographic authentication, and certification does not establish factual truth. |
| The artefact runs without language-model API access. | Deterministic workflow functions; pinned dependencies; experiment documentation | All tests, workflows, result generation, and table generation are local after dependency installation. | Installing dependencies may require package-index access; the study does not evaluate stochastic LLM behavior. |
| The checker accepts exactly the documented executable fragment. | JSON-admissibility definition and checker--calculus correspondence in `main.tex`; `prototype/checker.py`; shape tests | The correspondence covers the six ground schemas, their canonical JSON types, known actors, non-empty identifiers, and projected ledger state. | This is not completeness for unrestricted SELL derivations or arbitrary implementation events; opaque local state and framework metadata lie outside the projected ledger. |
| The submission package is mechanically checkable. | `scripts/build_submission.py`; `scripts/validate_submission.py`; `make submission-check` | The builder creates a flat editable bundle and the validator checks objective Array constraints and isolated compilation. | Mechanical validation does not replace author review or Editorial Manager metadata checks. |
| The revision has a citable immutable release. | GitHub release `v1.0.0`; signed release attestation; asset SHA-256 inventory; `CITATION.cff` | The software, manuscript, and separately licensed synthetic-data asset are bound to the tagged release. | No Zenodo record or archival DOI is claimed; citations use the exact public release and asset URLs. |

## Reporting Rule

Use "accepted," "rejected," or "strictly detected" only for the checker outcomes
defined by the experiment runner. Do not translate those terms into "safe,"
"correct," "secure," "truthful," or "production-ready."
